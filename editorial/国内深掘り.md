# 国内深掘り（editorialVersion = 1）

**先に [共通.md](共通.md) を読むこと。** ここには国内深掘り固有の規則だけを書く。

由来: Cowork スキル `domestic-news-digest` v2.2（2026-08-19）。
リポジトリへの移植にあたり、守備範囲・階層・出力先を変更した。変更点は末尾の改訂履歴にある。

---

## 目的

読者は日本経済新聞電子版の定期購読者である。日々の主要ニュースは日経で把握できる。
それでもこの系統を必要としている理由は次の3点であり、ここに最適化する。

1. 日経1紙だけでは視点が偏るため、**複数媒体を横断した**重要度順の整理がほしい
2. 各紙を個別に開いて読む・戻る・選ぶという反復作業を省きたい
3. 国内で流通しているニュースが、**英語圏メディアではどう扱われているか**という比較の視点もほしい

日経は購読しているが、この中では他媒体と完全に同列に扱う。有料記事だからといって特別な注記や優遇はしない。

**最大の品質基準は「当日性」と「媒体横断」である。** 分量でも文章の巧みさでもない。
前日以前のニュースを当日欄に置いた時点で、この成果物は目的を果たしていない。

## 守備範囲

**政治・経済・金融の深掘りが主題である。**

| 扱い | 対象 |
|---|---|
| 深掘り（`deep`） | 政治、経済、金融、財政、社会政策、制度 |
| 短信（`brief`） | 社会・事件・災害・地方の事案。上記のうち深掘りの枠に入らなかったもの |
| **扱わない** | **AI・IT・科学技術**。AI日報が持つ |

AI・IT・科学技術を扱わないのは、AI日報が ITmedia・Impress Watch・Publickey・GIGAZINE を含む媒体で
同じ領域を毎日30件拾っているためである。従来あった「テクノロジー&イノベーション」セクションは廃止した。

ただし**政治経済の事案としてのテック**は扱ってよい（例：大手プラットフォームへの行政処分、半導体政策の予算措置）。
判定は「これは制度・政策・市場の話か、製品・技術の話か」で行う。前者なら国内深掘り、後者なら AI日報。

## 基本媒体（8媒体、優先度は均等）

NHK、朝日新聞、読売新聞、日本経済新聞、毎日新聞、産経新聞、共同通信、時事通信

**媒体充足の下限: 8媒体のうち最低5媒体に実際に当たること。**
NHKと日経の2媒体だけで完結した場合、それは収集不足であり「媒体横断」という目的を満たしていない。
5媒体未満で終わった場合は、その理由を `productionNote` に明記する。

**この下限は `access: "body"` だけでなく `access: "excerpt"` でも満たされる。**
ペイウォールや取得拒否で本文が読めなくても、検索結果の抜粋でその媒体の報道内容を確認できたなら1媒体として数える。

民放（TBS/日テレ/テレ朝）、地方紙は基本媒体を補完する形での引用は可。ただし基本媒体の代替としてカウントしない。

### 取得しやすさの実測

- 全文取得しやすい … NHK
- 途中から有料になることが多い … 日経、朝日、読売、毎日
- 取得を拒否されることがある … 産経
- 本文が直接は取れない … 共同通信、時事通信（**転載先をたどれば読める。[共通.md](共通.md) 3節**）

たどり先の例: 中日新聞Web、沖縄タイムス、東京新聞、神戸新聞、琉球新報、デイリースポーツ、Yahoo!ニュース。
**日経の有料記事も、同じ事象を共同・時事が配信していれば、その転載先で本文が読める。**

### 分野特化の一次媒体を1回探す

基本8媒体は総合媒体である。特定分野のニュースには、その分野の一次媒体が別に存在し、数字が揃っていることが多い。
**深掘りの記事について、分野の専門媒体を1回だけ探す。**

| 分野 | 一次媒体 |
|---|---|
| 金融・金利 | 日本相互証券、日銀、財務省の一次発表 |
| 経済統計 | 内閣府 経済社会総合研究所、大和総研などのシンクタンク |
| 農業 | 日本農業新聞、JAcom（農業協同組合新聞） |
| 医療 | m3、日経メディカル |
| 地方の事案 | 当該県の県紙 |

基本8媒体の代替としてカウントしないが、数値の裏取りと精度向上に直結する。

## 定例チェック項目（毎回必ず確認）

その日に発表された定例の重要情報を機械的に確認する。これを飛ばすと「深掘りが2件しかない日」が発生する。

- **経済統計** … GDP速報、CPI、日銀短観、雇用統計、貿易統計、機械受注
- **金融政策** … 日銀金融政策決定会合、その前後の観測報道
- **市場** … 長期金利・為替・日経平均の大きな変動、為替介入
- **政治** … 閣議決定、法案の提出／可決、党大会、内閣人事
- **災害・事故** … 継続中の災害の当日更新値

## 検索の実務

- 日付ベースの検索（「国内ニュース 9月18日」）はカテゴリのトップページを返しやすい。
  **事象の種類で検索する**（「GDP速報」「長期金利」「閣議決定」＋おおまかな日付）
- 検索スニペットだけで書かない。候補が定まったら記事本文を取得し、具体的な数値・固有名詞・発言者名を確認する
- 同じテーマを複数媒体が報じている場合は最も詳しい1本に統合し、要約は自分の言葉で行う（引用の連結はしない）

## セクション構成

`section` に入れる値と、その中身。

| `section` | 名称 | 深掘り | 短信 |
|---|---|---|---|
| `new` | 今日の新展開 | 4〜6件 | — |
| `ongoing` | 継続ストーリーの進展 | 2件まで | 2〜4件 |
| `world-on-japan` | 英語圏は日本の何を報じているか | 0〜2件 | — |
| `brief` | 短信 | — | 4〜6件 |

### 総量と件数

**目標: 深掘り 6〜8件、短信 6〜8件、合計 12〜16件、記事本文の合計 5,000〜7,000字。**

移植前は全件を深掘り（12〜14件 × 約700字 = 約16,000字）で書いていた。
読者から「要約としては長すぎる」という評価があったため、**総量をおよそ半分にし、幅は保つ**。原資は社会・事件の短信化から出る。

- セクションを丸ごと省略する場合は `productionNote` に「本日は該当なし」と理由を書く。無言での省略は禁止
- 件数が下限を割る場合も `productionNote` に理由を1行書く。**下限割れが2日続く場合は収集手順を疑う**
- `world-on-japan` のみ下限0件でよい（無理に捻出しない）

### セクション振り分けの判定

- 本日初報、または本日大きく動いた → `new`
- 昨日以前の発表だが本日も継続進行中 → `ongoing`（本日分の差分がなければ不採用）
- 上記いずれでもない → **不採用**。件数を埋めるために古いニュースを繰り上げない
- **昨日初報＋本日新展開**は `new` に置いてよい。ただし初報日と本日の動きを本文で分けて書く（「17日に報じられ、18日に取引先が反応した」）。初報日を本日に繰り上げない

## 「英語圏は日本の何を報じているか」

目的は記事の網羅ではない。**国内報道と比べて何が違って見えるか**を拾うこと。

対象媒体: BBC、Reuters、Financial Times、Bloomberg、NYT、Washington Post、Guardian、AP

**The Japan Times、Tokyo Weekender、NHK World、Kyodo English など日本国内発の英語媒体は主ソースにしない。**
目的は「国外の視座から見た日本」であり、国内媒体の英語版では視座が変わらない。補助的な言及は可。

### 採用基準

以下のいずれかに該当し、かつ確信度が高い場合のみ採用する。

- 国内では大きく報じられていない、または扱いが薄い
- 着眼点・フレーミングが明確に異なる（例：同じ減税策を国内は「有権者の受け止め」、英語圏は「与党内の政治力学」で報じている）

### 不採用とするもの

- **速報値の更新ラグによる数字のズレ**（例：行方不明者が英語圏は1人、国内は2人）。これは編集タイミングの差であって、フレーミングの差ではない
- 単なる翻訳記事、国内報道の英訳
- 国内発の英語媒体のみを根拠とするもの

確信度が低い場合は採用しない。**0件の日があってよい。**
ただし**本文を取得できなかったことだけを理由に0件にしない。** 抜粋でその媒体の見立て・表現を確認できたなら帰属して書いてよい。

### 節の構成

このセクションの深掘りは、他と節が違う。

`概要`（1〜2文。英語圏メディアが日本について何を報じているか） → `国内報道との差`（1〜2文。扱いの薄さ、または着眼点の違いを明示。推測が混じる場合は「〇〇の論調では」「直接の言及はないが」など根拠の質を示す）

呼称の割れは国内媒体どうしでも起きる（同じ装備を「攻撃型ドローン」と書く媒体と「迎撃用ドローン」と書く媒体が同日に併存するなど）。
これは英語圏との比較に劣らず価値のある観察なので、見つけたら `国内報道との差` に書いてよい。ただし帰属の確認は同じ基準で行う。

## 今日の教養（2件）

本日採用した記事の中から2件を選び、各**300字±50**で解説する。`essays` に入れる。

### 選定の3層フィルター

1. **構造的奥行き** … 制度史・国際比較・条約・前例といった、ニュース本体に書かれていない層があるか
2. **今日の理解に効くか** … 解説が今日のニュースの咀嚼に直接効くこと
3. **他で読めない角度か** … **ニュース記事が既に書いている情報の要約ではダメ**

3を最も厳しく見る。本文で既に書いた数字を教養で繰り返すのは、字数の半分を無駄にしている。**本文と重複する数字は1つまで。**

**短信を題材にしてよい。** むしろ短信＋教養の組み合わせが望ましい。短信が幅を、教養が深さを担当する分業になるためである。
深掘りは本文で既に厚いので、教養で重ねると重複が増える。

条文・数字の紹介に終始せず、「なぜそうなっているか」「他で読めない論点は何か」を必ず1つは含める。
論点の切り替わり（背景→現状→課題）で2〜3回改行を入れる。一塊の長文ブロックにしない。

**教養の題材が当日性を欠く記事だった場合、その教養も成立しない。** 不採用にした記事を題材に使わない。

## 出力前の自己検証（国内深掘りの追加分）

[共通.md](共通.md) 10節に加えて確認する。

- [ ] `new` の全記事が本日初報または本日大きく動いたものか。世論調査は**調査実施日**を確認したか
- [ ] 共同通信・時事通信の記事について、転載先を1回探してから `headline` と判定したか
- [ ] 深掘りの記事について、分野特化の一次媒体を1回探したか
- [ ] 基本8媒体のうち何媒体に当たったか（`excerpt` を含めて数える）。**5未満なら再収集する**
- [ ] 定例チェック項目（統計・金融政策・市場・政治・災害）を1周したか
- [ ] **AI・IT・科学技術の記事が混じっていないか。**製品・技術の話は AI日報 の守備範囲である
- [ ] 深掘りが政治・経済・金融に寄っているか。社会・事件が深掘りを占めていないか
- [ ] `world-on-japan` の各件は、更新ラグではなく着眼点の差か
- [ ] 教養は300字±50か。改行が2〜3回入っているか。本文と重複する数字が2つ以上ないか
- [ ] 深掘り6〜8件・短信6〜8件・本文合計5,000〜7,000字に収まっているか

## 改訂履歴

**v1（2026-09-20）** — Cowork スキル `domestic-news-digest` v2.2 をリポジトリへ移植。変更点は4つ。

1. **「テクノロジー&イノベーション」セクションを廃止。** AI日報が AI・IT・科学技術を毎日30件拾うため、守備範囲が完全に重なっていた。移植前の2026-09-17版では、このセクションの4件（ドコモの個人情報無断提供・Gyazo流出・シャープのAIサーバー参入・無人タクシー）がすべて ITmedia と INTERNET Watch 発であり、AI日報 の媒体と同一だった。
2. **2階層（深掘り／短信）を導入。** 移植前は全件を約700字の深掘りで書き、総量が約16,000字あった。読者評価は「要約としては長すぎる」。深掘り6〜8件・短信6〜8件とし、総量をおよそ半分にする。1件あたりの深掘りの分量（600〜800字）は評価が高かったため変えない。
3. **保存先を Google Drive から リポジトリの JSON へ変更。** 直近3日分の確認も Drive ではなく `public/data/archive/` を読む。
4. **制作記録（※注記）を紙面から分離**し `productionNote` へ移した。

移植元 v2.2 までの改訂履歴と失敗実例は [共通.md](共通.md) に統合した。
