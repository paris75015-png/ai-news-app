# AI日報（editorialVersion は `pipeline/editorial.js` の `EDITORIAL_VERSION`）

**先に [共通.md](共通.md) を読むこと。**

ただしこの系統だけは、人ではなくコードが生成する。**実際の指示文は [`pipeline/editorial.js`](../pipeline/editorial.js) にある。**
このファイルは、他の系統と並べて読めるようにするための説明である。方針を変えるときは `editorial.js` を編集する。

---

## 目的

AI・IT・科学技術の当日の動きを、**広く浅く**一覧できるようにする。
国際深掘りが「少数の事案を深く」担当するのに対し、こちらは「多数の事案を浅く」担当する。

読者はAIとテクノロジーに関心のある日本の社会人で、毎朝限られた時間でニュースを読む。

## 守備範囲

| 扱い | 対象 |
|---|---|
| 扱う | AI、IT、科学技術。技術・製品・研究の話 |
| **扱わない** | **経済・金融・政治・国際情勢・社会問題**。制度・政策・市場の話 |

境界の判定は「**技術・製品・研究の話か、制度・政策・市場の話か**」で行う。
「AI企業の資金調達」「半導体メーカーの決算」のように、テクノロジー企業そのものの動向は対象に含む。
「大手プラットフォームへの行政処分」「半導体政策の予算措置」は扱わない（国内は日経が担当する）。

## 階層

深掘りは作らない。ただし**短信でもない。** 全件が「要約」という独自の形式である。
専門用語の多い業界の話なので、短信（150〜250字）まで削ると理解できなくなる。多少長くなっても、読んで分かることを優先する。

| 項目 | 規定 |
|---|---|
| 要約 | 2〜4段落・400〜900字が目安。専門用語には初出で短い説明を添える。本文があるのに250字未満なら、別のモデルで書き直す |
| 見出し | 30〜45字（50字を超えない） |

共通.md の短信の字数・見出し30字の規定は適用しない。JSON の `depth` は画面の都合で `brief` のままにしている。

記事の大きさは、重要度の段階（`tier`）で紙面の段組みのように変える。

| 段階 | 件数 |
|---|---|
| 必読 | 3 |
| 読むべき | 7 |
| 興味があれば | 10 |
| 時間があれば | 残り |

点数ではなく**その日の順位**で段階を決める。点数だけで分けると、同じような点数が並んだ日に強弱が付かないため。

## 設定値（`pipeline/editorial.js`）

| 項目 | 値 |
|---|---|
| 掲載件数 | 30件 |
| カテゴリー | AI / IT / 科学 |
| カテゴリー枠 | 最低3件・最大15件 |
| 掲載の下限 | 40点。件数が足りない日は31点まで緩める。守備範囲外の記事は30点以下にさせているので、緩めても紙面に戻らない |
| 採点モデル | Claude Haiku 5.5（2026-11-01 から。それまでは Gemini 無料枠） |
| 要約モデル | Claude Haiku 5.5（2026-11-01 から。それまでは上位10件が Groq の GPT-OSS、残りが Gemini） |
| 再掲防止 | 一度載せた記事は14日間除外（`data/seen.json`）。同じ日の再実行では除外しない |
| 同じ出来事・同じテーマ | 同じ出来事は1件だけ。直近3回分の紙面に載せた出来事は、状態が進んだ続報を除き載せない。同じテーマは3件まで |
| 失敗時の再試行 | 採点が失敗したら、1・3・5・10分待ってやり直す。採点が通らないと紙面が出ないため。要約は1回だけやり直す |
| 時間制限 | 要約は20分で打ち切り、処理全体は60分で強制終了 |

取得元は [`pipeline/sources.js`](../pipeline/sources.js) の12媒体。
**採用の条件は「記事ページから本文を最後まで取得できること」**。本文が取れない媒体は要約の質が落ちるため採用しない。

## 重複の防ぎ方

AI日報は毎朝の処理の最後に走る。`pipeline/build.mjs` が次の3段構えで落とす。

1. **URL の一致** … `intl.json` の当日分から URL を集め、正規化して突き合わせる（コードで確実に消える）
2. **国際深掘りと同じ出来事** … その見出しを採点の指示文に添え、URL が違っても同じ出来事なら 0 点にして末尾へ回させる
3. **紙面の中の重複**（`dropDuplicateEvents`、version 12 から）… 上位70件を専用の1回の呼び出しで出来事ごとにまとめ、
   同じ出来事の2件目以降・直近3回分の紙面の再掲・同じテーマの4件目以降を落とす。
   2026-10-09 の紙面で、必読3件がすべて同じ発表（Google Cloud の Gemini Agent）になったため加えた

国際深掘りが動かなかった日は、1と2を飛ばして通常どおり30件を作る。3の判定が失敗した日は、落とさずにそのまま進める。

## 品質について（実測）

- 仕組みは安定している。直近の定期実行は30件すべてに本文と要約が付き、点数も95〜33に分散した
- **残る弱点**：無料枠の混雑度合いで、日によって担当モデルが変わり品質がぶれる
- **確認できた誤りは見出しに集中している**（要約本文の数値は元記事と一致していた）。
  固有名詞の取り違え・現職/前職の取り違えは機械照合で検出できるようになったが、すべては防げない。
  **重要な記事は元記事で確認する前提**で読む
- AI同士の比較（同一6記事）では、Groq の GPT-OSS は情報量が多く数値も正確だった。
  ただし段落指示を無視することがあり、役職の音写誤訳（AI czar →「AIシザー」）や現職/前職の取り違えがあった。
  Gemini Flash-Lite は簡潔で形式は守るが、情報量が少なく、数値の方向を誤った例（国債利回りの上昇↔低下）があった
