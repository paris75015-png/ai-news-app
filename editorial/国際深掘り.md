# 国際深掘り（editorialVersion = 3）

**文体は [共通.md](共通.md) の第1節・第2節（段落の割り方）・第3節（確度ラベル）・第7節（誤情報）に従う。**
第4節（当日性）・第5節（継続）・第9節（収集〜push の手順）は、この系統では**適用しない**。収集は Actions が済ませており、この系統の手順は下に書く。

改訂（version 2、2026-10-01）：検索で集めて書く方式をやめた。クラウドの実行環境は本文の取得を遮断されるため、検索の抜粋だけで書くことになり、「深掘り」の名に値しなかった。
今は Actions が先に複数媒体の**本文**を集めた「資料」を用意し、この系統はそれを読んで書く。

改訂（version 3、2026-10-08）：深掘りが浅いという指摘を受けた。原因は2つあった。
①字数と構成が小さかった（900〜1,300字、各社の紹介が中心）。②本文を読める媒体が少なかった（18媒体のうち、実際に本文を読めたのは毎回2〜4媒体）。
①は字数を広げ、「論点ごとの比較」の節を足した。②は資料づくり側で、取得できる媒体を増やした（下の「資料の読み方」）。**それでも読めない媒体は読めないままで、ない袖は触れない。** 材料が薄い日は、薄いと書いて短く終わる。

---

## 目的

世界の報道機関が数日にわたって取り上げ続けている話題について、**媒体ごとの見え方の違い**を読み解く。

初日の報道は速報で、各社が似た内容になる。**2日目・3日目に、各社の力点・解釈・思惑が分かれる。** そこを書く。
日経を読んだうえで、なお足りない視点を補うのが役割である。

## 材料は資料だけ

`data/dossiers/{本日}-*.json` が、本日書く話題である。**ファイルの数だけ書く（0〜3件）。** 1件もなければ何も書かず、そのことを報告して終わる。

資料の中身

| 項目 | 内容 |
|---|---|
| `title` / `firstSeen` / `daysSeen` | 話題の題、初出の日、記録された日数（2〜3） |
| `history` | 日付 → 世界の注目度（0〜100）。続いているか、落ち着いたかが分かる |
| `coverage` | 取り上げた媒体の数（海外 n/N、国内 n/N）。国内が少なければ「日本の媒体は薄い」 |
| `sources[]` | 媒体ごとの見出しと、`access: "body"` なら本文（`text`）。`"excerpt"` はフィードの要約文だけ。`"headline"` は見出しだけ |
| `japan` | 日本が当事者の話題か |

**検索・WebFetch・記憶で事実を足してはならない。** 資料にないことは書かない。書けないところは書けないと言う。
`access: "headline"` の媒体は、見出しから言えること以上を、その媒体の主張として書かない。

### 資料の読み方（version 3 で追加）

- `excerpt`：フィードの要約文（数文）だけを読めた媒体。要約文に現れた範囲だけを、その媒体の主張として書いてよい。全体の論調や「何を省いたか」は言えない（要約文では省略かどうかが分からない）
- `method`：`direct`（直接取得）または `reader`（読み取り代行経由）。`reader` の本文は、表の脚注・囲み記事・広告文が混じることがある。本文として読めない断片は使わない
- `wire`：本文の末尾に通信社の署名があった媒体（`Reuters`・`AP`・`AFP`）。**同じ通信社の配信を載せた媒体は、独立した1媒体として数える**。署名が検出されなくても、同じ文面の記事が複数あれば同じ扱いにする
- `bodyCount` と `excerptCount`：資料の作成時点の数。通信社の重複は差し引いて数え直す
- 見出しだけの媒体どうしの見出しの違い（例：「報復を警告」と「協議を歓迎」）は、本文がなくても材料になる。ただし「見出しの言葉の違い」としてだけ書く

## 書くもの（1話題＝深掘り1件、1,500〜2,200字）

節の構成（`body` の各要素の `label`）

1. **経過**（250〜400字）：初出から今日までに何が起きたか。各日の注目度の動きにも一言触れる。論点の背景のうち、資料の本文に書かれているものは、ここで短く置く
2. **各社の見え方**（600〜900字）：本文を読めた媒体ごとに、**何を中心に据えたか・何を省いたか・どんな言葉で呼んでいるか**を書く。媒体名を主語にする。3媒体以上を取り上げる。引用できる発言・数字は、誰の発言かを添えて入れる
3. **論点ごとの比較**（300〜500字）：媒体をまたいで同じ論点を並べる。たとえば「原因」「責任の所在」「数字」「今後の見通し」。**媒体ごとに数字や呼び方が食い違う点は、必ずここで対照する**（例：A社は3,600億ユーロ、B社は1日10億ユーロ）。食い違いの理由が資料から言えなければ「資料からは断定できない」と書く
4. **視点の差**（200〜300字）：見え方が分かれた理由として、資料から言えることだけを書く。言えなければ「資料からは断定できない」と書く。**末尾に、推測を「ここは推測」と明示してまとめる**
5. **日本との関わり**（任意・100〜250字）：`japan` が true のとき、または資料の本文に日本が出てくるときだけ書く。**それ以外は節ごと省く**（定型文で埋めない）。
   `coverage.jp` が 0 でも「日本の媒体は扱っていない」とは書かない。測っているのは日本の5媒体の見出し上位だけで、扱いの有無までは言えない。書くなら「測定した日本の5媒体の見出しには出ていない」と正確に書く

### 材料が薄い日の書き方

- 独立した本文が 3 媒体以上：上の字数で書く
- 独立した本文が 2 媒体：書く。ただし「読めたのは2媒体の本文で、比較は限られる」と経過の直後に一文で断る。「論点ごとの比較」は食い違いが実際にあるときだけ置く。字数は 1,200字を下限としてよい
- 独立した本文が 1 媒体以下：深掘りにせず、`excluded` に理由を書いて見送る。1媒体の本文から「各社の見え方」は書けない
- **字数を満たすために、同じ内容を言い換えて膨らませない。** 材料が足りなければ短く終わる

**書いてはならないこと**
- 資料にない背景・数字・人名
- 「〜とみられる」「〜だろう」の推測を、媒体の主張と混ぜること。推測は節の末尾にまとめ、「ここは推測」と明示する
- 本文を読んでいない媒体の主張を、読んだかのように書くこと

## 出力

`public/data/intl.json`（当日分）と `public/data/archive/{本日}-intl.json`（同じ内容）。型は [src/article.js](../src/article.js)。

- `stream`: `"intl"`、`depth`: `"deep"`、`section`: `"followup"`
- `id`: `intl-{date}-{資料の id}`
- `headline`: 日本語・30字以内。事実の見出しにする（「〜を読み解く」のような題にしない）
- `score`: 資料の最新の注目度をそのまま入れる。自分で採点しない。`tier` は 50以上 must、30以上 should、それ未満 interest（注目度は 0〜100 の別の尺度で、旧版の「掲載下限 70」は適用しない）
- 通信社の配信記事（Reuters 配信を ABC や Straits Times が掲載、など）は、`outlet` を通信社、`via` を掲載した媒体にし、媒体数は1と数える
- `sources[]`: 資料の `sources` から、**書くのに使った媒体**を入れる。`access` は資料のとおり。本文を読んだ媒体は `note` に確認できた要点を一文で書く
- `bodyAvailable`: **独立した**本文（通信社の重複を1と数える）が 3 以上なら true、未満なら false
- `continuity`: `{ previousDate: firstSeen, previousScore: 初日の注目度, note: 続いている理由 }`
- `model`: `"claude-sonnet-5-5"`（この実行のモデル正式名）、`editorialVersion`: 3、`essays`: `[]`
- `productionNote`: `reachedOutlets`（本文を読めた媒体）、`unreachedOutlets`（見出しだけの媒体）、`excluded`（資料はあるが書かなかった話題と理由）、`counts`、`text`（自由記述）

資料が 1 件もない日は `intl.json` を書き換えない。

## 出力前の自己検証

- [ ] 事実がすべて資料の中にある（`excerpt` の媒体は、要約文に現れた範囲だけ）
- [ ] 各社の見え方で、本文を読めた媒体だけを「主張」として書いている
- [ ] 段落が割れている（1段落は 3〜4 文）。一文は 60字以内
- [ ] 媒体間で食い違う数字を、「論点ごとの比較」で対照した
- [ ] 字数が下限未満なら、材料が薄いためだと `productionNote.text` に書いた
- [ ] 推測が明示されている
- [ ] JSON が妥当で、`public/data/intl.json` とアーカイブが同じ内容
