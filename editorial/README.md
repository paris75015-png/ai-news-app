# 編集方針

3つの系統の編集方針を、ここ1か所にまとめている。

| 系統 | 方針 | 生成するのは | 出力先 |
|---|---|---|---|
| 国内深掘り | [国内深掘り.md](国内深掘り.md) | クラウドの定期実行（Claude Sonnet 5） | `public/data/domestic.json` |
| 国際深掘り | [国際深掘り.md](国際深掘り.md) | クラウドの定期実行（Claude Sonnet 5） | `public/data/intl.json` |
| AI日報 | [AI日報.md](AI日報.md) と `pipeline/editorial.js` | GitHub Actions（Gemini / Groq・無料枠） | `public/data/ai.json` |

3系統に共通する規則は [共通.md](共通.md) にある。**各方針を読む前に必ず共通.md を読むこと。**

## 役割分担

読者は日本経済新聞の電子版を購読しており、**全体の網羅は日経が担当する**。
この3系統は、日経を読んだうえでなお足りないものを補う。したがって網羅ではなく、分担が優先する。

```
国内深掘り  政治・経済・金融。日経1紙では取れない媒体横断の視点
国際深掘り  日本で報道が薄い論点。戦争・大災害の速報は書かない（日本でも十分報道される）
AI日報      AI・IT・科学技術。広く浅く、当日の動きを一覧で
```

## 実行順と重複の防ぎ方

平日のみ、この順で走る。**後から走る系統が、先に出た当日分を読んで除外する。**

```
07:00 JST  国内深掘り  → public/data/domestic.json
07:30 JST  国際深掘り  → public/data/intl.json      （domestic.json を読む）
16:43 JST  AI日報      → public/data/ai.json        （両方を読む）
```

重複防止のための別の台帳は作らない。先に出た JSON がそのまま除外リストになる。

守備範囲で物理的に分けてあるため、重複はそもそも起きにくい。
それでも重なるのは「テック企業の政治経済ニュース」のような境界の事案である。
その場合は**先に出た系統が優先**し、後から走る系統は落とす。

## 変更したとき

編集方針を変えたら、各方針の冒頭にある `editorialVersion` を1つ上げる。
生成された JSON に記録されるので、後から「いつの方針で作った紙面か」を追える。
